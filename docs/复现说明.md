# 复现说明

> 目标：任何人拿到这个仓库，按本文命令从头跑一遍，能得到与 `docs/技术方案.md` 记录一致的 CV 与提交文件。

## 0. 前置条件

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows（macOS / Linux 只需把 PowerShell 换行符换成 `\`，其余命令通用） |
| uv | ≥ 0.5，`winget install --id=astral-sh.uv -e` |
| 磁盘 | 约 3 GB（数据 26 MB + 环境 1.5 GB + 中间产物 1 GB） |
| CPU | 4 核可跑，建议 8 核以上；8 核跑完整流程约 3 小时 |

⚠️ **不要用系统自带的 Python**。本机系统 Python 是 MinGW/ucrt64 构建，装不上 pandas / LightGBM 的 MSVC wheel。所有命令都通过 `uv run`，它用 `.venv` 里由 uv 下载的标准 CPython 3.12。

## 1. 环境

```powershell
git clone <repo> && cd Pump-it-Up
uv sync --locked
uv run python -c "import pandas, sklearn, lightgbm, catboost, xgboost; print('env ok')"
```

`--locked` 保证按 `uv.lock` 安装；如果 `pyproject.toml` 与锁文件不一致会直接报错。

## 3. 一键流程

```powershell
# 3.1 清洗 → data/processed/base.parquet（约 5 秒）
uv run python -m src.data

# 3.2 固定折划分（首次运行 train 时自动生成 data/processed/folds.npy）
#     所有实验共用同一份折，换了折分数就不可比

# 3.3 训练六个成员模型（耗时按 8 核估算）
uv run python -m src.train --name E5b  --model catboost                       # ~20 min  CV 0.8115
uv run python -m src.train --name E7   --model catboost --features v2         # ~35 min  CV 0.8111
uv run python -m src.train --name E9   --model catboost --params-file configs/e9.json   # ~50 min  CV 0.8106
uv run python -m src.train --name E10  --model lgbm --seed 7                  # ~2 min   CV 0.8024
uv run python -m src.train --name E11  --model lgbm --features v2             # ~3 min   CV 0.8033
uv run python -m src.train --name E12  --model catboost --seed 2024 --params-file configs/e12.json  # ~50 min  CV 0.8110

# 3.4 等权集成 → submissions/sub_ENS8.csv（约 10 秒）
uv run python -m src.ensemble --members E5b E7 E9 E10 E11 E12 --name ENS8 --equal
```

期望结果：`equal-weight blend: 0.8163`，并在 `submissions/` 下生成 `sub_ENS8.csv`（14,850 行，格式已自动校验）。

**为什么用等权而不是搜索权重**：权重搜索 / stacking 会在 OOF 上过拟合。实测 ENS2（LR stacking，OOF 0.8162）榜分 0.8208，反而低于 ENS1（网格权重，OOF 0.8147）的 0.8212 —— OOF 上的 +0.0015 没有兑现。等权不拟合任何参数，是更稳的选择。

## 7. 踩过的坑（复现时可能遇到）

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `TypeError: must be real number, not NAType` | CatBoost 不接受 categorical 里的 `pd.NA` | 已由 `models.to_catboost_frame` 填成 `"missing"` 并转 string |
| `Category index must contain only values of the same type` | XGBoost 不支持 boolean 类别 | 已由 `models.to_xgb_frame` 转字符串 |
| `ImportError: pyarrow required` | parquet 缺引擎 | `uv add pyarrow`（已在依赖里） |
| `JSONDecodeError` 传 `--params` | PowerShell 5.1 会吞掉内联 JSON 的引号 | 改用 `--params-file configs/*.json` |
| 改了 `pyproject.toml` 后 `uv sync --locked` 报错 | 锁文件未更新 | `uv lock && uv sync` |
| 分数比文档低 0.001~0.002 | 单次 5 折的折间标准差约 0.004 | 差别在噪声内，看整体是否一致 |

## 8. 从零到提交的最短路径

如果只想复现出提交文件、不关心中间对照实验：

```powershell
uv sync --locked
uv run python -m src.data
uv run python -m src.train --name E5b --model catboost
uv run python -m src.train --name E10 --model lgbm --seed 7
uv run python -m src.ensemble --members E5b E10 --name QUICK --equal
```

两个模型约 22 分钟，CV 0.8131（比完整集成低 0.003），足以验证整条链路通畅。
