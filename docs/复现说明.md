# 复现说明

> 目标：任何人拿到这个仓库，按本文命令从头跑一遍，能得到与 `docs/技术方案.md` 记录一致的 CV 与提交文件。

## 0. 前置条件

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows（macOS / Linux 只需把 PowerShell 换行符换成 `\`，其余命令通用） |
| uv | ≥ 0.5，`winget install --id=astral-sh.uv -e` |
| 磁盘 | 约 3 GB（数据 26 MB + 环境 1.5 GB + 中间产物 1 GB） |
| CPU | 4 核可跑，建议 8 核以上；8 核跑完整流程（含分区成员与高折数）约 **2 小时** |

⚠️ **不要用系统自带的 Python**。本机系统 Python 是 MinGW/ucrt64 构建，装不上 pandas / LightGBM 的 MSVC wheel。所有命令都通过 `uv run`，它用 `.venv` 里由 uv 下载的标准 CPython 3.12。

## 3. 一键流程（复现最终版 CV 0.8233 / 公开榜 0.8277）

全套在本机（8 核）约 **2 小时**。想只要一个能提交的文件，直接跳到 §8。

```powershell
# 3.1 清洗 → data/processed/base.parquet（约 1 秒）
uv run python -m src.data

# 3.2 CB 族：CatBoost 10 折 + 5 折 + per-region CatBoost
uv run python -m src.train --name E5b    --model catboost                    # ~10 min  CV 0.8115（5 折）
uv run python -m src.train --name CB_k10 --model catboost --folds 10        # ~21 min  CV 0.8135（10 折）
uv run python -m src.cluster_model --name CLregion --by region --model catboost --folds 5   # ~62 min  CV 0.8122

# 3.3 RF 族：四个配置 × 20 折（每配置约 4 分钟）
uv run python -m src.train --name RF10_k20 --model rf --folds 20 --params-file configs/rf_mf025.json
uv run python -m src.train --name RF6_k20  --model rf --folds 20 --params-file configs/rf_mf020.json
uv run python -m src.train --name RF7_k20  --model rf --folds 20 --params-file configs/rf_mf030.json
uv run python -m src.train --name RF9_k20  --model rf --folds 20 --params-file configs/rf_leaf3_mf030.json

# 3.4 PART 族：分区 RF × 10 折（共约 11 分钟）
uv run python -m src.cluster_model --name CLRF_region_k10   --by region  --folds 10 --params-file configs/rf_mf025.json
uv run python -m src.cluster_model --name CLRF_wptype_k10   --by wptype  --folds 10 --params-file configs/rf_mf025.json
uv run python -m src.cluster_model --name CLRF_kmeans12_k10 --by kmeans --clusters 12 --folds 10 --params-file configs/rf_mf025.json

# 3.5 族等权融合 → submissions/sub_LEAN.csv（约 10 秒）
uv run python -m src.ensemble --families configs/families_lean.json --name LEAN
```

期望结果：

```
  CB       members=3  family acc=0.8154
  RF       members=4  family acc=0.8183
  PART     members=3  family acc=0.8190
family-equal blend: 0.8233 (no parameters fitted)
```

### 3.6 为什么要分族，而不是所有成员一起等权

直接 10 个成员等权会把权重变成 RF 4 票、CB 3 票、PART 3 票（40% : 30% : 30%）。`--families` 先族内平均、再族间等权，每个族一票。

`configs/families_full.json` 是包含 ET / LGB 两族的五族版本（CV 0.8222），用于对照——**弱族会被稀释**，不是越多越好。

**为什么用等权而不是搜索权重**：权重搜索 / stacking 会在 OOF 上过拟合。实测 ENS2（LR stacking，OOF 0.8162）榜分 0.8208，反而低于 ENS1（网格权重，OOF 0.8147）的 0.8212 —— OOF 上的 +0.0015 没有兑现。等权不拟合任何参数，是更稳的选择。

## 7. 踩过的坑（复现时可能遇到）

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| `TypeError: must be real number, not NAType` | CatBoost 不接受 categorical 里的 `pd.NA` | 已由 `models.to_catboost_frame` 填成 `"missing"` 并转 string |
| `Category index must contain only values of the same type` | XGBoost 不支持 boolean 类别 | 已由 `models.to_xgb_frame` 转字符串 |
| `ImportError: pyarrow required` | parquet 缺引擎 | `uv add pyarrow`（已在依赖里） |
| `JSONDecodeError` 传 `--params` | PowerShell 5.1 会吞掉内联 JSON 的引号 | 改用 `--params-file configs/*.json` |
| 改了 `pyproject.toml` 后 `uv sync --locked` 报错 | 锁文件未更新 | `uv lock && uv sync` |
| 分数比文档低 0.001~0.002 | 单次 5 折的折间标准差约 0.004 | 差别在噪声内，看整体是否一致 |
| `--families` 报 `missing OOF for ...` | 成员 `.npy` 未生成 | 先按 §3 对应命令训练该成员 |
| 合成了 5 折和 20 折成员，担心不可比 | 每行的 OOF 都来自“没见过该行”的模型，混用合法；高折数成员在 CV 与提交两边同时受益 | 无需处理，但**不要**把折数差异当成调参信号 |
| 分区成员在小分组上崩溃 | 某个类别在子集里完全缺失，`predict_proba` 列数变少 | 已由 `cluster_model._aligned_proba` 按 `classes_` 回填对齐 |

## 8. 从零到提交的最短路径

### 8.1 只想验证链路通畅（约 12 分钟，CV 0.8131）

```powershell
uv sync --locked
uv run python -m src.data
uv run python -m src.train --name E5b --model catboost
uv run python -m src.train --name E10 --model lgbm --seed 7
uv run python -m src.ensemble --members E5b E10 --name QUICK --equal
```

得到 `sub_QUICK.csv`（CV 0.8131），足以确认数据、环境、提交格式都正常。

### 8.2 想要接近最终分数（约 2 小时，CV 0.8233 → 公开榜 0.8277）

按 §3 的 3.2 ~ 3.5 全部跑完。真正不可省的是 **折数**（`--folds 10/20`）与 **分区成员**（`cluster_model`）：它们分别贡献 +0.0036 与 +0.0044，而所有特征工程与融合技巧的增益合计接近 0。
