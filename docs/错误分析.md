# 错误分析（阶段 7）

> 数据：训练集 59,400 条，用**最终集成**（三族等权：CB / RF / PART，共 10 个成员，`configs/families_lean.json`）的 **OOF 预测**，不是训练集内的拟合值。
> 整体准确率 **0.8233**，即 10,495 条判错；对应公开榜 **0.8277**（偏差 +0.0044）。
> 早期版本（ENS8，0.8163）的旧数字已全部替换。

## 1. 错误集中在哪

### 1.1 按类别

| 类别 | 样本数 | 占训练集 | 判对 | 这类贡献的错误数 |
| --- | --- | --- | --- | --- |
| `functional` | 32,259 | 54.3% | 91.5% | 2,755 |
| `non functional` | 22,824 | 38.4% | 78.8% | 4,838 |
| `functional needs repair` | 4,317 | 7.3% | 32.8% | 2,902 |

**`needs repair` 只占 7.3% 的样本，却贡献了 27.7% 的错误。** 它的判对率 32.8%，是整体准确率的真正瓶颈：

| 真实标签 | 预测为 functional | 预测为 needs repair | 预测为 non functional |
| --- | --- | --- | --- |
| needs repair | **53.6%** | 32.8% | 13.7% |

一半以上的「需维修」被判成「正常」，这是最危险的一类错误 —— 对维护调度来说，漏掉需要维修的泵比误报更糟。

> 从 0.8163 到 0.8233 的 +0.0070 中，`needs repair` 的判对率只从 31.2% 升到 32.8%（多对 69 条），**大部分增益来自另外两类**：`functional` 90.8%→91.5%、`non functional` 78.2%→78.8%。这佐证了「该类的上限受限于标签本身」的判断。

### 1.2 按地区（样本数 ≥ 300）

| region | 样本数 | 准确率 |
| --- | --- | --- |
| **Kigoma** | 2,816 | **72.5%** |
| Kagera | 3,316 | 78.6% |
| Mara | 1,969 | 78.8% |
| Mbeya | 4,639 | 79.1% |
| Arusha | 3,350 | 79.6% |

Kigoma 比整体低 9.8 个百分点，且这个缺口从 ENS8 时代（71.3%）到现在几乎没有缩小 —— 分区成员虽然把它当作独立子问题建模，但**该区域的可用线索本身就少**。

### 1.3 按水井类型

| waterpoint_type | 样本数 | 准确率 |
| --- | --- | --- |
| **hand pump** | 17,488 | **76.6%** |
| **improved spring** | 784 | **77.4%** |
| communal standpipe | 28,522 | 83.6% |
| communal standpipe multiple | 6,103 | 85.2% |
| other | 6,380 | 90.4% |

`hand pump` 是第二大类别（29% 的样本），却比 `communal standpipe` 低 7.0 个百分点。**手压泵的维修状态更难从现有字段推断** —— 它往往由单户或村组自行维护，`scheme_name` / `funder` 这类字段大量缺失，模型缺少可依赖的管理线索。

正因为这个缺口稳定存在，「按 `waterpoint_type_group` 分区」的成员（`CLRF_wptype_k10`）单模型就能拿到 **0.8178**，是集成里最强的一员之一。

### 1.4 按水量

| quantity | 样本数 | 准确率 |
| --- | --- | --- |
| **seasonal** | 4,050 | **73.5%** |
| **insufficient** | 15,129 | **77.3%** |
| enough | 33,186 | 82.7% |
| unknown | 789 | 87.1% |
| dry | 6,246 | 97.4% |

两端很好判（`dry` 97.4% 几乎必坏，`enough` 82.7%），**中间态最难**：`seasonal` / `insufficient` 的水井既可能正常、也可能损坏，正是模型最犹豫的一批，而它们合计占 32% 的样本。

### 1.5 按井龄

| 井龄（年） | 样本数 | 准确率 |
| --- | --- | --- |
| < 5 | 11,630 | 85.7% |
| **5–10** | 5,627 | **81.0%** |
| 10–20 | 9,456 | 81.4% |
| 20–30 | 5,633 | 82.9% |
| 30–50 | 6,203 | 83.7% |
| > 50 | 133 | 85.7%（样本过少，仅供参考）|

仍呈 **U 形**：新井（<5 年）几乎都正常，老井要么早坏了要么维护得好，都容易判；**5–20 年的中期井**处在「该坏没坏」的灰色区间，最难判。

另外，`construction_year` 缺失（记为 0）的 20,709 条样本准确率 **80.6%**，比已知井龄的 **83.2%** 低 2.6 个百分点 —— 缺失本身携带「管理不规范」的信息，但这批样本可依赖的线索更少。

### 1.6 按水源 / 取水方式 / 付费方式

| 字段 | 最差取值 | 准确率 | 最好取值 | 准确率 |
| --- | --- | --- | --- | --- |
| `source_class` | surface | 80.8% | groundwater | 82.8% |
| `extraction_type_class` | handpump | 76.3% | motorpump | 91.2% |
| `payment_type` | on failure | 79.7% | annually | 86.3% |

注意 `on failure`（坏了才付钱）这个付费方式：直觉上「按次付费」应该意味着维护积极性高、状态更好，但它恰恰是准确率最低的一档（79.7%）。原因是这类水井的付费记录本身就是「曾经坏过」的信号，与标签存在反向因果，模型难以从这一列稳定推断。

## 2. 错误的结构性原因

1. **类边界本身模糊**：`functional` 与 `needs repair` 是同一个现场调查员的一次主观判断，同一条水井在不同调查中可能被判成两类。这构成**标签噪声下限** —— 无论模型多好，这部分都无法拟合。
2. **needs repair 的样本太少**：4,317 条（7.3%），且没有单字段能分离它。模型在 accuracy 目标下自然会把它推向多数类。已实测：把 3 类问题拆成 OvR / OvO / 层级两级（两种拆法都试过）对整体准确率的影响在 ±0.0004 内，**结构不解决问题，信息才解决**。
3. **手压泵缺管理线索**：`scheme_name` 在训练集缺失 48.5%，手压泵更严重，而「谁在管」恰恰是状态的最强决定因素之一。
4. **中期井的灰色区间**：5–20 年井龄的准确率最低，符合「设备寿命接近临界点、状态高度依赖维护」的常识。

## 3. 已验证的方向与结论

本文早期版本列过四个「该往哪投」，现在它们都已有实测结果：

| 方向 | 实测结论 | 状态 |
| --- | --- | --- |
| 对 `hand pump` / 区域单独建子模型 | **有效**：分区成员（region / wp_type / kmeans）单独 0.8154~0.8178，作为族并入后贡献 +0.0044 | ✅ 已采纳 |
| 对 `needs repair` 做二阶段判别 | **中性**：层级分解 0.8151 vs 单阶段 0.8150（RF 对照） | ❌ 放弃 |
| 给弱类加权重 / 调阈值 | **负收益**：类别乘子最优 α≈0.95，等于不动 | ❌ 放弃 |
| 继续堆全局特征 | **三次验证无效**：v2 0.8111、v3 0.8098，均低于 v1 0.8115 | ❌ 放弃 |
| 继续加更多同类模型 | **负收益**：族间等权时，弱族（ET 0.8109 / LGB 0.8047）会被稀释 | ❌ 放弃 |

真正有效的两个方向都指向「**让模型看到更多有效信息**」：

1. **分区成员**：把「区域 / 水井类型」当条件建模，而不是让一个全局模型去拟合所有模式；
2. **提高折数**：5→10→20 折，每个模型多看 10~15% 数据、测试端平均更多模型（实测 +0.0036）。

## 4. 复现

```powershell
# 最终集成（CV 0.8233）的 OOF 切片，需先备好 configs/families_lean.json 中的 10 个成员
uv run python -m src.ensemble --families configs/families_lean.json --name LEAN

# 自己算任意切片的准确率
uv run python -c "
import numpy as np, pandas as pd
from src import config, data

train, _ = data.load_base()
y = train.status_group.map(config.CLASS_TO_CODE).to_numpy()
fams = [[\"CB_k10\",\"E5b\",\"CLregion\"],
        [\"RF10_k20\",\"RF6_k20\",\"RF7_k20\",\"RF9_k20\"],
        [\"CLRF_region_k10\",\"CLRF_wptype_k10\",\"CLRF_kmeans12_k10\"]]
load = lambda n: np.load(config.DATA_PROCESSED / f'oof_{n}.npy')
proba = np.mean([np.mean([load(m) for m in fam], axis=0) for fam in fams], axis=0)
pred = proba.argmax(1)
print('overall', (pred == y).mean())
slice_ = train.waterpoint_type.astype(str)
print(pd.DataFrame({'s': slice_, 'ok': pred == y}).groupby('s').ok.agg(['size', 'mean']))
"
```
